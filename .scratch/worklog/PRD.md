# PRD: 作業ログ（WorkLog）

Status: spec / 仕様策定中
更新日: 2026-08-30

## 1. 目的

タスクに対して時系列で作業記録を書き足せるようにする。蓄積された記録は
**日報・週報の材料として AI（Claude Code 等）に読ませて要約させる**ことを主目的とする。

したがって本機能の成否は次の2点で決まる。

1. **書かれること** — 手動記録なので、入力が面倒なら数日で途絶え材料がゼロになる。
2. **期間で取り出せること** — AI に渡す経路が用意されていること。

## 2. ユビキタス言語（CONTEXT.md に追記する）

| 用語 | 定義 |
|------|------|
| 作業ログ (WorkLog) | タスクに対して時系列で追記される作業記録。1件＝本文＋記録日時。編集・削除は可能だが、上書きではなく積み上げていく点で `memo` と異なる。 |

### 既存 `memo` との棲み分け

| | 性質 | 用途 |
|---|---|---|
| `tasks.memo` | 上書き・現在の状態 | 「今このタスクは何か」 |
| 作業ログ | 追記・時系列 | 「いつ何をしたか」＝日報の材料 |

両者は役割が異なるため**共存させる**。`memo` は廃止しない。

## 3. スコープ

### やること

- 手動入力の作業ログ（1件＝自由文の本文のみ）
- タスク詳細モーダルからの入力・閲覧
- クイック入力ウィンドウからの追記
- CLI での期間指定エクスポート（日報を AI に書かせる経路）

### やらないこと（今回は対象外）

- **自動イベントログ**（列移動・完了などの履歴の自動記録）。ノイズが増えて AI 要約の
  質が落ちるため、まずは手動記録のみで運用し、必要になってから `kind` 列を足して拡張する。
- **種別タグ・作業時間の記録**。入力コストを上げると記録自体が続かないため、本文のみで開始する。
- アプリ内タイムラインビュー（フェーズ5・後回し）

## 4. データモデル

### マイグレーション `004_work_logs.sql`

```sql
CREATE TABLE IF NOT EXISTS work_logs (
  id           TEXT PRIMARY KEY,   -- ULID（IDだけで時系列ソートが効く）
  task_id      TEXT NOT NULL,      -- 外部キーは張らない（後述）
  project_id   TEXT NOT NULL,      -- 非正規化。期間×プロジェクトの抽出が日報の基本クエリ
  body         TEXT NOT NULL,      -- 自由文。空文字は不可
  task_title   TEXT NOT NULL,      -- 記録時点のタスク名スナップショット
  project_name TEXT NOT NULL,      -- 記録時点のプロジェクト名スナップショット
  created_at   TEXT NOT NULL,      -- ISO8601 / UTC（既存テーブルと同じ）
  updated_at   TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_work_logs_created ON work_logs(created_at);
CREATE INDEX IF NOT EXISTS idx_work_logs_task    ON work_logs(task_id, created_at);
```

### 決定: タスク削除後も作業ログを残す

`task_id` / `project_id` に **外部キー制約を張らない**。既存テーブルは全て
`ON DELETE CASCADE` だが、作業ログだけは例外とする。

理由: タスクを整理した瞬間に過去の作業記録が消えると、先週・先月の日報が
再生成できなくなる。日報の材料としての価値が失われる。

### 決定: タスク名は「記録時点のスナップショット」を持つ

削除時にスナップショットを埋める方式ではなく、**ログ作成時に `task_title` /
`project_name` を書き込む**。

理由:

- 削除時に埋める方式だと、タスクが消える経路が4つ（タスク削除／カラム削除の
  CASCADE ／プロジェクト削除の CASCADE ／CLI のプロジェクト削除）あり、
  全てにフック実装が必要になる。漏れると記録が欠損する。
- 記録時に書けば INSERT 1回で完結し、フックはゼロ。
- 日報の文脈では「作業した当時のタスク名」の方がむしろ正確。

表示・出力時は `LEFT JOIN tasks` して
`COALESCE(t.title, wl.task_title)` を使い、**タスクが生きていれば現在名、
削除済みならスナップショット名**を出す。JOIN 結果が NULL であることが
「削除済みタスクのログ」の判定にもなる。

### 孤児ログの掃除

削除済みタスクのログは自動では消えない。掃除手段（`log prune --before <date>` 等）は
将来必要になった時点で追加する。今回は実装しない。

## 5. 時刻の扱い（重要）

- 保存は既存テーブルと同じく `toISOString()`＝**UTC**。
- 日報の「今日」は **JST のローカル日付**。
- したがって CLI の `--from` / `--to` は **ローカル日付として受け取り、
  UTC 範囲に変換して比較する**。
  - `--from D --to D` → `[D 00:00 JST, D+1 00:00 JST)` を UTC に変換した半開区間
- ここを UTC 文字列の前方一致で済ませると、**JST 00:00〜09:00 の記録が前日扱い**になる。
  日報が毎朝ずれるので、日付境界変換は必ずテストを書く。

## 6. 入力導線

### 6-1. タスク詳細モーダル（必須）

`src/components/TaskDetailDialog.tsx` を拡張。

- 既存フィールドの下に「作業ログ」セクション
- 上部に入力欄（複数行 textarea）＋追加ボタン。`Ctrl+Enter` で確定
- 下に既存ログを**新しい順**で一覧表示（日時＋本文）
- 各ログに編集・削除。削除は確認ダイアログ（既存 `ConfirmDialog` を再利用）
- 本文が空白のみの場合は追加不可

### 6-2. クイック入力ウィンドウ（必須）

既存の `quick` ウィンドウ（`--quick` でタスク追加）を壊さず、**別 argv で
ログ追加モードを起動する**。

- 起動: `app.exe --quick-log`（AHK で `--quick` とは別ホットキーに割り当てる）
- Rust 側 `setup()` の argv 分岐に `--quick-log` を追加し、`quick` ウィンドウを
  ログモードで表示する

**対象タスクの指定方法（要確認・推奨案）**

推奨は「**インクリメンタル検索で選択、既定値は直近ログを書いたタスク**」。

- ウィンドウを開くと対象タスク欄に直近ログ対象タスクが入っている
- そのままでよければ本文を打って `Ctrl+Enter`（＝連続記録が最速）
- 違うタスクならタイトル数文字を打って絞り込み選択

代替案とその評価:

- **直近更新タスク（`updated_at` 最新）を既定にする** — カンバンを D&D しただけで
  対象が変わるため誤爆しやすい。却下。
- **「作業中タスク」という新概念を導入し、カードから作業開始/終了を切り替える** —
  日報用途との相性は非常に良く将来的には有望だが、ドメイン概念が1つ増え
  スコープが大きく膨らむ。今回は見送り、将来の拡張候補とする。

### 6-3. CLI からの追加（任意・フェーズ外）

`app.exe log add <task-id> --body "..."` は DB 層を共有すれば実装コストはほぼゼロで、
AI エージェントが作業しながら記録を残せる価値がある。ただし今回の必須スコープには含めない。

## 7. 出力（日報を AI に書かせる経路）

### 7-1. CLI（優先実装）

```
app.exe log list [--from YYYY-MM-DD] [--to YYYY-MM-DD] [--project <名前またはID>]
```

- `--from` / `--to` 省略時は**今日**（ローカル日付）
- 出力は **Markdown**。用途が「AI に読ませる」に限定されるため、既存の
  テーブル形式ではなく AI が構造を掴みやすい形式にする
- プロジェクト → タスクの順にグルーピングし、同一タスク内は時刻昇順
- 削除済みタスクは末尾に `(削除済み)` を付ける

出力例:

```markdown
# 作業ログ 2026-08-30

## 開発

### API のリトライ処理を実装
- 09:15 仕様を確認。既存の指数バックオフを流用できそう
- 11:40 実装完了。タイムアウト時のテストが1件落ちる

### DBマイグレーション整理 (削除済み)
- 14:02 004 に統合して不要になったので削除
```

該当なしの場合は `(該当する作業ログなし)` を出力（既存 CLI の慣習に合わせる）。

これにより「今日の日報作って」の一言で、AI が `log list` を叩いて要約できる。

### 7-2. アプリ内タイムラインビュー（後回し）

## 8. ウィンドウ間同期

`src/lib/events.ts` にイベントを追加する。

| イベント | ペイロード | 用途 |
|---|---|---|
| `worklog:added` | `{ taskId, projectId }` | クイックウィンドウでの追記をメインウィンドウへ反映 |

CLI からの追加はイベントを発火しないため、既存方針どおり
メインウィンドウのフォーカス復帰時の再フェッチで同期する。
