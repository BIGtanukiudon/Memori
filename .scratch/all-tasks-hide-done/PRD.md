# PRD: 全タスク画面で完了列のタスクを除外する

Status: implemented / 実装済み
更新日: 2026-10-29

## 1. 目的

全タスク画面で、複数プロジェクトにまたがる未完了のタスクを確認しやすくする。各プロジェクトの完了列にあるタスクを、1つの操作で一覧から除外できるようにする。

## 2. 画面・操作

既存のフィルタ領域に、ラベルが **「完了列のタスクを除外」** のチェックボックスを追加する。配置は「列」の直後とし、狭い画面では既存のフィルタと同様に折り返す。

| 状態 | 動作 |
|------|------|
| OFF（チェックなし） | 完了列のタスクも一覧の対象にする。 |
| ON（チェックあり） | 各タスクの所属プロジェクトで指定された完了列にあるタスクを一覧から除外する。 |

- 切り替えた時点で表示を更新する。適用ボタンは設けない。
- ラベルのクリックでも切り替えられ、Tabでフォーカス、Spaceで切り替えできる。
- 読み上げ時にラベルとチェック状態を取得できる、標準のチェックボックスを使う。
- 初期値は **OFF** とする。既存の「全タスクを対象に表示する」初期動作を引き継ぐ。

## 3. 完了列の判定

用語はルートの `CONTEXT.md` と ADR-0001 に従う。

対象タスクの所属プロジェクトを特定し、次の両方を満たす場合に除外する。

1. そのプロジェクトの `doneColumnId` が設定されている。
2. タスクの `columnId` が、その `doneColumnId` と一致する。

- プロジェクトごとに判定する。プロジェクトを「すべて」にしている場合も、それぞれの完了列が対象になる。
- 完了列が未設定のプロジェクトでは、このフィルタによる除外は発生しない。
- 列名（例: `Done`、`完了`）は判定に使わない。同名でも完了列に指定されていない列は除外しない。
- `completedAt` の有無は判定に使わない。完了列の指定変更だけでは既存タスクの完了日時が更新されないため、現在の所属列と指定を基準にする。
- 所属プロジェクトを取得できていないタスクは、このフィルタだけを理由に除外しない。プロジェクト情報の取得・更新後に再判定する。

## 4. 既存フィルタ・並び替えとの組み合わせ

- プロジェクト、列、優先度、期日、検索の各条件と **AND条件** で適用する。
- ON/OFFの切り替えで、他のフィルタや並び替えの選択は変更しない。
- プロジェクトを変更した場合、既存仕様どおり列フィルタを「すべて」に戻す。「完了列のタスクを除外」のON/OFFは維持する。
- 列の選択肢には完了列も残す。完了列を選択したまま除外をONにすると、結果は0件になる。フィルタの自動解除や列選択の変更は行わない。
- 絞り込み後のタスクに既存の並び替えを適用する。初期の並び替えは優先度の降順とする。
- 結果が0件の場合は、既存の **「該当するタスクはありません」** を表示する。チェックボックスは引き続き操作できる。
- 表示されたタスクをクリックすると、従来どおりタスク詳細を開く。

## 5. フィルタ状態の保持とデータ更新

- 全タスク画面を表示している間は、タスクやプロジェクト情報が更新されてもON/OFFを維持する。
- カンバン画面に移動してから全タスク画面に戻った場合は、既存フィルタと同様に初期値へ戻す。アプリ再起動時もOFFとする。
- 設定の永続化は行わない。
- タスクが完了列へ移動した場合、最新データの反映後に一覧から消える。完了列から移動した場合は、他の条件を満たせば再表示する。
- 完了列の指定・変更・解除が反映された場合も、現在の指定に従って再判定する。完了列がAからBに変わった場合、Aのタスクは表示対象に戻り、Bのタスクを除外する。
- フォーカス復帰や既存の更新イベントで再取得する際は、タスク・列に加え、判定に必要なプロジェクトの最新の完了列指定も反映する。全タスク用の再取得でプロジェクト・列・タスクをまとめて取得する。
- 外部操作の反映タイミングは既存の同期方式に従う。常時ポーリングは追加しない。

## 6. 実装方針

- 全タスク画面のフィルタ状態に、完了列のタスクを除外する真偽値を追加する。
- タスク絞り込み処理に、プロジェクトごとの完了列指定を参照できるようにする。現在の画面はすでにプロジェクト一覧を受け取っているため、その情報を利用する。
- タスク一覧、フィルタ状態、プロジェクトの完了列指定の変更を、表示の再計算に反映する。
- チェックの切り替えによる絞り込みは、取得済みデータに対して行う。切り替えごとのDB問い合わせは不要。
- DBスキーマの変更は不要。フィルタ操作でタスクや完了日時を更新しない。
- 機能実装時はTDDで進め、READMEの全タスク一覧ビューの説明に本フィルタを追記する。

## 7. 受け入れ条件

以下の「表示」は、他のフィルタ条件を満たしていることを前提とする。

| # | 条件・操作 | 期待結果 |
|---|-----------|----------|
| 1 | 全タスク画面を開く | チェックはOFF。完了列のタスクも表示される。 |
| 2 | チェックをONにする | 完了列のタスクだけが除外され、通常列のタスクは表示される。 |
| 3 | ONからOFFへ戻す | 除外されていたタスクが再表示される。他の選択条件は維持される。 |
| 4 | 異なる完了列を持つ複数プロジェクトを横断表示し、ONにする | 各プロジェクトの完了列のタスクが除外される。 |
| 5 | 完了列が未設定のプロジェクトでONにする | そのプロジェクトのタスクは除外されない。 |
| 6 | `Done`という名前の通常列と、別名の完了列がある状態でONにする | 別名の完了列のタスクだけが除外される。 |
| 7 | 完了列にあるが`completedAt`がnullのタスクでONにする | タスクは除外される。 |
| 8 | 通常列にあるが`completedAt`が設定済みのタスクでONにする | タスクは表示される。 |
| 9 | プロジェクト・列・優先度・期日・検索の各フィルタと併用する | 各条件と完了列の除外条件の両方を満たすタスクだけを表示する。 |
| 10 | 完了列を列フィルタで指定してONにする | 0件のメッセージを表示する。OFFに戻すと該当タスクを表示する。 |
| 11 | ONのままプロジェクトを変更する | ONは維持され、列フィルタだけが「すべて」に戻る。 |
| 12 | ONのまま並び替えを変更する | 完了列のタスクを除いた一覧が、選択した順に並ぶ。 |
| 13 | ONのままタスク移動・完了列の指定変更・解除の最新データを反映する | 最新の所属列と完了列指定に従って表示が更新され、ONは維持される。 |
| 14 | ONのまま再取得し、その後カンバン画面を経由して戻る | 再取得ではONを維持し、画面を開き直した際はOFFに戻る。 |
| 15 | 全タスクが完了列にある場合、またはタスクが0件の場合にONにする | 0件のメッセージを表示し、フィルタを操作できる。 |
| 16 | キーボードでチェックを切り替える／表示された行をクリックする | チェックと表示が連動し、行クリックで対象タスクの詳細が開く。 |

## 8. 検証方針

- 主な検証は、既存の全タスク画面のコンポーネントテストで行う。ユーザー操作と表示結果を確認し、内部の状態構造には依存しない。
- 完了列の判定は、既存のタスク絞り込み処理の単体テストでも確認する。複数プロジェクト、未設定、列名・完了日時との不一致を含める。
- データ更新は、画面へ渡すタスクとプロジェクト情報を更新して確認する。外部更新からの再取得では、プロジェクトの完了列指定まで更新される経路も確認する。
- 機能実装時に関連テストと型チェックを実行し、既存フィルタと並び替えの動作も確認する。

## 9. 対象外

- 完了タスクだけを表示するモード。
- カンバン画面、クイック入力、作業ログの検索候補、CLIへの同フィルタの追加。
- フィルタ設定の永続化や全フィルタの一括リセット。
- 完了列の指定方法、タスクの完了日時の記録方法の変更。

## 10. 初期値・状態保持の方針

初期値はOFF、画面を開き直した際の状態はリセットとする。どちらも既存の全タスク画面の挙動に合わせた仕様を採用した。
